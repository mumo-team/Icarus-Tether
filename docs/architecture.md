# 아키텍처

## 전체 흐름

1. AI 에이전트가 도구를 호출하면 **프록시(A)**가 가로챈다.
2. 동시에 비신뢰 콘텐츠(이메일·웹)는 **오픈웨이트 인젝션 탐지 모델(C)**이 판독해 신뢰도 점수를 만든다.
3. **브레인(B)**이 세션의 누적 오염 태그 + 인자에 실린 태그를 모아 트라이펙타 여부를 판정한다.
4. 통과하면 실제 도구(DB·메일·파일)로 전달되고, 결과는 **PII 마스킹(C)**을 거쳐 에이전트에 반환된다.
5. 차단되면 사람 승인을 요청한다.
6. 모든 판정은 감사로그에 서명되어 기록되고 대시보드에 실시간 표시된다.

## 프록시의 투명성

프록시는 에이전트에게는 "내가 서버다"라고 응답하고(initialize 핸드셰이크), 실제 다운스트림 MCP 서버에는 "내가 클라이언트다"라고 연결한다.
양쪽 다 코드 수정이 필요 없는 투명 프록시 패턴이다.

## 트라이펙타 판정 로직

```
IF   호출 대상이 OUTBOUND_SINK
AND  세션에 SENSITIVE 태그가 있음
AND  세션에 UNTRUSTED_ORIGIN 태그가 있음
THEN 차단 + 감사기록 + 사람 승인 요청
```

## 검증된 정화 (차별화 지점)

기존 taint 추적 도구(예: lilith-zero)는 세션 단위로 태그를 누적만 하고 지우는 기능이 없어,
시간이 지날수록 정상 작업까지 막히는 문제가 있다.

Icarus-Tether는 토큰화(TOKENIZATION)·구조화 추출(STRUCTURED_EXTRACTION) 같은 검증된 방법을 통과한
데이터에 한해 태그를 안전하게 해제(declassify)해, 세션이 계속 정상 작동하도록 한다.

구현 위치: `policy-engine/src/index.ts`의 `attemptSanitization()`
