# 아키텍처

## 전체 흐름

프록시가 에이전트와 실제 MCP 서버 사이에 끼어, 데이터가 오가는 **모든 채널**을 정책 엔진의
판정에 태운다. 판정은 전부 결정론 코드이며 AI/LLM 호출이 0건이다.

1. 에이전트가 도구를 호출하면 **프록시(A)**가 `tools/call`을 가로채 `ToolCallContext`로 포장한다.
2. **정책 엔진(B)**이 판정한다 (`evaluateToolCall`) — 아래 [판정 규칙](#트라이펙타-판정-규칙) 참조.
3. 판정은 해시체인 감사로그(`proxy/audit.log`)에 기록되고, 웹소켓(7331)으로 **대시보드(C)**에 실시간 방송된다.
4. **통과**면 실제 서버로 중계하고, 돌아온 결과를 `recordToolResult`로 오염 계보에 기록한다.
   기록에 실패하면 결과를 에이전트에 전달하지 않고 막는다 (fail-safe — 추적 안 된 데이터를 흘리지 않는다).
5. **차단**이면 실제 서버를 호출하지 않고, 사람이 읽을 설명(`explanation`)을 돌려준다.
   오버라이드 가능한 차단에 한해 `approvalId`를 함께 발급해, 사람이 승인한 뒤 재시도하면 1회 통과한다.

이와 별개로 비신뢰 출처 콘텐츠는 **ML 인젝션 탐지**(`proxy/src/injection.ts`)가 점수를 매겨
대시보드에 표시한다. 이 점수는 **차단 판정에 관여하지 않는다** — 보조 관측 신호이며, 없거나
틀려도 핵심 차단은 그대로 동작한다.

> 프록시는 도구 결과를 **가공하지 않고 원본 그대로** 에이전트에 돌려준다. 우리 방어는 "결과를
> 마스킹해서 안전하게 만드는 것"이 아니라 "위험한 흐름 자체를 실행 전에 막는 것"이다.
> (대시보드의 `maskPii`는 정화 전/후 비교 화면의 예시 렌더링 전용이며, 프록시 경로와 무관하다.)

## 프록시의 투명성

프록시는 에이전트에게는 "내가 서버다"라고 응답하고(initialize 핸드셰이크), 실제 다운스트림 MCP
서버에는 "내가 클라이언트다"라고 연결한다. 양쪽 다 코드 수정이 필요 없는 투명 프록시 패턴이다.

## 트라이펙타 판정 규칙

기본 운영 모드는 **값 단위 계보 판정**(`judgmentMode: "lineage"`)이다.
세션 전체가 아니라 **지금 나가려는 그 값**의 계보를 따진다.

```
IF   호출 대상이 OUTBOUND_SINK
AND  valueSensitive        (나가는 값이 실제로 민감 데이터를 담고 있는가)
AND  sessionExposure       (세션이 비신뢰 입력에 노출된 적이 있는가)
THEN 차단 + 감사기록 + (오버라이드 가능하면) 사람 승인 제안
```

| 축 | 판정 근거 | 왜 이렇게 보는가 |
|---|---|---|
| `valueSensitive` | ① 값의 계보에 `SENSITIVE`가 살아있음 ② 출력-스캔이 값의 *내용*에서 민감 원본·비밀키 발견 ③ 정화 전 볼트 원본을 그대로 재전송 | 민감은 "실제로 나가는가"의 문제라 **값**으로 본다. 값이 민감을 안 실었으면 통과시켜 과차단을 줄인다 |
| `sessionExposure` | 세션이 `UNTRUSTED_ORIGIN`을 한 번이라도 획득했는가 (grow-only — 정화로 꺼지지 않음) | 비신뢰는 "제어흐름을 조작했는가"의 문제라, 본문을 안 실어도 위험하다. **세션**으로 본다 |

이 **비대칭**이 정밀함의 핵심이다. 세션 단위 boolean 판정(`judgmentMode: "session"`, 구버전)
대비 오탐이 절반으로 줄고 미탐도 낮다 — 수치와 근거는 [`policy-engine/README.md`](../policy-engine/README.md) §4.

`sessionExposure`가 grow-only인 이유: 정화로 이 축을 끌 수 있으면, 비신뢰 노드만 정화해
U축을 세탁한 뒤 무관한 민감 데이터를 유출하는 우회가 열린다.

## 검사하는 채널

`tools/call` 하나만 막으면 나머지 채널로 새기 때문에, 데이터가 지나는 모든 경로를 같은 강도로 본다.

| 채널 | 방향 | 처리 |
|---|---|---|
| `tools/call` | 에이전트 → 서버 | `evaluateToolCall` — 트라이펙타 + 파괴 게이트 |
| `resources/read`·`prompts/get` | 요청 | `evaluateResourceRequest` — 비신뢰 URI로 나가는 요청은 "읽기"라도 sink 강도로 검사 (URI에 데이터를 실으면 유출구) |
| `resources/read`·`prompts/get` | 응답 | `recordExternalContent` — 외부 콘텐츠를 오염 파이프라인에 태워 `sessionExposure`를 켠다 |
| `sampling/createMessage` | 서버 → 에이전트(역방향) | `evaluateOutboundContent` — LLM 응답이 서버로 되돌아가는 실제 유출구라 하드 블록 |
| 그 외 메서드 | — | 위험도 분류 후 `FORWARDED`로 감사기록·방송하며 중계 (무검사 통과를 진짜 통과와 구분해 가시화) |

## 파괴적 액션 게이트

유출과 **직교인 별도 축**이다. "삭제 자체"가 아니라 "**비신뢰가 유발한** 파괴"만 막는다.

- 사용자가 채팅으로 직접 시킨 삭제는 오염 그래프에 들어오지 않으므로(노드는 도구 결과에서만 생성)
  구조적으로 통과한다 — 비개발자의 정상 삭제를 방해하지 않는다.
- 비신뢰 콘텐츠를 읽은 뒤의 삭제만 HITL 승인을 요구한다.
- 정화로는 해제되지 않는다. "외부 내용이 시킨 삭제"라는 사실은 값을 가려도 변하지 않기 때문이다.

## 검증된 정화 (차별화 지점)

기존 taint 추적 도구(예: lilith-zero)는 세션 단위로 태그를 누적만 하고 지우는 기능이 없어,
시간이 지날수록 정상 작업까지 막히는 문제가 있다.

Icarus-Tether는 토큰화(`TOKENIZATION`)·구조화 추출(`STRUCTURED_EXTRACTION`) 같은 **검증된 방법을
통과한** 데이터에 한해 태그를 안전하게 해제(declassify)해, 세션이 계속 정상 작동하도록 한다.
검증에 실패하거나 설정에 근거(스키마·패턴)가 없으면 태그를 유지한다 (fail-safe).

구현 위치: [`policy-engine/src/index.ts`](../policy-engine/src/index.ts)의 `attemptSanitization()`

## 실패 처리 원칙

판정 계산이 예외를 던지면 **통과가 아니라 차단**한다. 유출 판정·파괴 게이트·역방향 판정·리소스
요청 판정 전부 try/catch로 차단을 반환하며, 조용히 통과하는 경로가 없다. 설정 파일이 잘못되면
기본값으로 떨어지지 않고 예외로 기동을 막는다 (fail-closed).

## 설정

도구 분류·판정 모드·정화 규칙은 전부 `policy-engine/config/*.json`에 있다. 코드에는 하드코딩된
정책이 없다. 데모용 설정은 `proxy/config/demo-registry.json`(계보 판정 + HITL + 파괴 게이트)이며,
`TAINTGUARD_TOOL_REGISTRY` 환경변수로 지정한다. 파일이 바뀌면 재시작 없이 다음 요청부터 반영된다
(검증 통과 시에만 교체 — 잘못된 설정은 기존 정책을 유지).
